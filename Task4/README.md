### **Функциональные требования**

|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
| 1 | Клиент | Запрос информации о депозитах по телефону | Клиент звонит в кол-центр, чтобы получить данные о депозитных ставках. |
| 2 | Кол-центр | Доступ к актуальным ставкам | Менеджер кол-центра получает актуальные данные о депозитах в своей системе. |
| 3 | Партнёрский кол-центр | Консультация клиентов | Операторы партнёрского кол-центра получают файлы с актуальными ставками. |
| 4 | АБС | Обновление ставок в центральной системе | Актуальные депозитные ставки хранятся в АБС и передаются в кол-центры. |

---

### **Нефункциональные требования**

|**№**|**Требование**|
| :-: | :- |
| 1 | Кол-центр должен получать актуальные ставки в реальном времени. |
| 2 | Передача данных в партнёрский кол-центр должна происходить в формате файлов (SFTP). |
| 3 | Обновление данных должно происходить с минимальной задержкой. |
| 4 | Хранение депозитных ставок должно быть централизованным в АБС. |
| 5 | Шифрование трафика для передачи чувствительных данных. |

---

### **Решение**

#### **Диаграмма контекста**
1. Клиент взаимодействует с кол-центром для получения информации.
2. Кол-центр получает актуальные ставки из АБС.
3. Партнёрский кол-центр получает обновлённые данные через SFTP.
4. АБС управляет хранилищем ставок.

#### **Диаграмма контейнеров**
- **Кол-центр** → API → **АБС (Хранение ставок)**.
- **Партнёрский кол-центр** → SFTP → **Актуальные ставки (Файлы)**.
- **Клиент** → **Кол-центр** (Запрос информации).

Архитектурные решения:
- **Хранение депозитных ставок в АБС** – упрощает доступ к актуальной информации.
- **Использование API** – минимизирует задержку передачи данных.
- **SFTP для партнёрского кол-центра** – соответствует техническим ограничениям.

---

### **Альтернативы**
1. **Использование REST API для партнёрского кол-центра**
   - **Плюсы:** Более оперативное обновление данных.
   - **Минусы:** Не поддерживается технически партнёрским кол-центром.

2. **Хранение ставок в отдельной базе данных для быстрого доступа**
   - **Плюсы:** Разгружает АБС, улучшает производительность.
   - **Минусы:** Требует синхронизации данных.

3. **Передача данных партнёрам через email**
   - **Плюсы:** Простота реализации.
   - **Минусы:** Возможность задержек в обновлении информации.

---

### **Недостатки, ограничения, риски**
- **Возможные задержки в обновлении ставок для партнёрского кол-центра** – зависит от расписания выгрузок файлов.
- **Нагрузка на АБС** – требуется анализ влияния API-запросов.
- **Безопасность данных** – требуется надёжное шифрование при передаче файлов.
- **Сложность масштабирования** – возможны проблемы при росте числа кол-центров.

---

### **Крупные задачи для каждой системы**

#### **АБС**
- Разработка API для предоставления ставок в кол-центры.
- Настройка механизмов выгрузки файлов для партнёрского кол-центра.

#### **Кол-центр**
- Интеграция с API АБС для получения актуальных ставок.
- Настройка внутренних процессов обновления информации.

#### **Партнёрский кол-центр**
- Приём и обработка файлов со ставками через SFTP.
- Внедрение внутренних инструментов работы с новыми ставками.

#### **Общий roadmap**
- **1-2 месяц** – Разработка API и настройка механизмов обновления ставок в АБС.
- **3-4 месяц** – Интеграция кол-центра с API, тестирование обновлений.
- **5-6 месяц** – Настройка передачи данных в партнёрский кол-центр и завершение внедрения.
- **12 месяцев** – Оптимизация работы и возможный переход на более современный механизм передачи данных.
